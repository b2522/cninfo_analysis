# 公告掘金

本地运行的巨潮资讯公告研判工作台。它将**抓取公告**与**模型分析**拆开：先按披露日期从巨潮资讯抓取沪深京公告并自动去重，再只对标题高召回筛选出的候选公告下载 PDF、调用 OpenAI 兼容模型，并保留带原文证据的相关结论。

## 工作流

1. 选择开始、结束日期，点击 **抓取公告**。
   - 后端以 POST 请求 `https://www.cninfo.com.cn/new/hisAnnouncement/query`，使用 `column=szse` 覆盖沪深京市场。
   - 每一页使用 `pageNum` 依次抓取，按 `announcement_id` 去重。
   - 重复抓取只更新公告基础信息，不覆盖已经确认的模型分析结果。
   - 抓取完成后，公告会立即以“待筛选”状态显示在默认表格中，便于核对抓取结果。
2. 点击 **分析未分析公告**。
   - 先用宽进严出的标题筛选，尽量避免漏掉可能重要的公告。
   - 标题未命中的普通公告会标记为“已排除”，不会下载 PDF 或调用模型；它们会从默认表格隐藏，但仍可在“全部抓取（含已排除）”中人工复核。
   - 标题命中的公告才下载 PDF 并交给模型根据正文与原文证据判定。
   - 已确认、已排除和失败的公告不会被自动重复调用；失败记录保留在表格中便于定位原因。
3. 在表格的“分析结果”表头中选择 **当前队列 / 全部抓取（含已排除）/ 机会 / 风险**，筛选展示结果。

表格列为：**时间｜代码｜简称｜公告标题｜分析结果**。默认“当前队列”会显示刚抓取的待筛选公告，以及待分析、分析中、已确认和分析失败的记录；完成标题筛选后被排除的普通公告不再干扰默认视图。如需确认是否遗漏，可切换至“全部抓取（含已排除）”。

## 信号分类

### 机会

- 业绩增长
- 并购重组和资产注入
- 回购、增持和股权激励
- 终止减持、未减持
- 产品获批、重大技术突破
- 产能投产和重大项目

### 风险

- 大股东减持、质押和股权变动
- 重大合同违约或经营风险
- 业绩大降

不分析大额订单/订单兑现，以及监管问询、审计意见、诉讼和担保等未列入上述分类的事项。

## 每日自动抓取

当本地服务保持运行时，程序会在**每天 19:00（Asia/Shanghai）**自动创建一次抓取任务，范围为当天和前一天两个自然日。例如，在 **2026 年 8 月 3 日** 19:00 触发的任务会抓取 **2026-08-02 至 2026-08-03** 的公告。

定时任务只负责抓取与去重，不会自动调用模型；模型分析仍由页面中的“分析未分析公告”按钮触发。关闭服务或服务未在 19:00 运行时，当天的定时触发不会补跑。

## 配置并启动

无需配置 MongoDB、数据库账号或 `.env`。启动后会自动创建本地 SQLite 文件：

```text
data/cninfo_announcement_mining.sqlite3
```

1. 启动：

```powershell
python run.py
```

2. 在浏览器打开 `http://127.0.0.1:8000`。

网页内填写 OpenAI 兼容 API 的 Base URL、Key 和模型名。模型配置保存于当前浏览器的 localStorage；后端只在执行分析任务时使用它，不写入本地 SQLite 文件或日志。

## 数据与安全边界

- 任务、公告、去重状态和分析结果仅保存到项目目录的 `data/cninfo_announcement_mining.sqlite3`。
- 原有远程 MongoDB 数据不会被读取、迁移或删除；切换后需要重新抓取公告。
- 不保存 PDF 二进制，只保存源 PDF URL、处理结果和内容哈希。
- 不使用、保存或打印浏览器 Cookie。
- 页面将公告标题、模型摘要和证据等不可信内容以纯文本 DOM 节点渲染，避免它们作为 HTML 执行。
