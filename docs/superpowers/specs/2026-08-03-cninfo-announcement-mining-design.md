# CNINFO 公告掘金设计说明

## 目标
构建一个仅在本机运行的 Web 应用：按披露日期从巨潮资讯发现沪深京公告，分析九类高价值事项，并提供可回溯的证据、置信度、任务进度和事件时间线。

## 已确认的范围

### 信号类别
1. 业绩大幅变化（仅正向：归母净利润同比增长 >= 50% 或扭亏；不含下滑、由盈转亏）
2. 并购重组和资产注入
3. 回购、增持和股权激励
4. 终止减持、未减持
5. 产品获批、重大技术突破
6. 产能投产和重大项目
7. 监管问询、审计意见、诉讼和担保
8. 大股东减持、质押和股权变动
9. 重大合同违约或经营风险

不包含大额订单/订单兑现；不包含由盈转亏。

### 工作流
- 快捷日期：最近 2 天、最近 3 天、最近一周、自定义。
- 日期标签只填值，用户点击“开始分析”才发起后台任务。
- 任务先分页取得公告元数据，标题/元数据初筛候选，下载 PDF 并提取文字，再由 OpenAI 兼容模型按 JSON Schema 复判。
- 高置信度要求明确事实/规则命中，且有 PDF 正文原文证据；证据不足归入中低置信度或待复核。
- 每份公告保留；疑似同一事项组织成事件时间线。
- 批处理采用低并发、退避和局部失败重试；单项失败不终止任务。
- 重新分析重新获取列表，但只重处理新增、修订、附件变化或失败项目。

### 界面
- 本地 Web 页面，四个视图：全部、机会、风险、待复核。
- 展示证券代码/名称、披露日期、标签、事件阶段、关键数值、置信度、证据片段、源公告链接和事件组。
- 设置页仅配置 OpenAI 兼容 API 的 Base URL、API Key、模型名。Key 存浏览器 localStorage，传到后端仅在运行内存保留。
- 不做导出、OCR、定时调度、推送、账号系统、云端部署或阈值编辑。

### 持久化与安全边界
- MongoDB 是唯一持久化存储。使用独立数据库 cninfo_announcement_mining。
- 保存公告元数据、提取文本、文件哈希、分类结果、任务、事件组；不保存 PDF 二进制。
- MongoDB 匿名连接仅作为个人测试环境使用。应用只读写自己的数据库和集合，绝不执行跨库管理或删除数据库操作。
- 不把巨潮 Cookie、模型 Key 或 MongoDB URI 写入源码、日志、MongoDB 或 Git。

## 技术设计
- Python 3.13，FastAPI，原生 HTML/CSS/JavaScript，MongoDB 驱动，httpx，PyMuPDF，pytest。
- FastAPI 提供 API、静态页面和进程内 BackgroundTasks/asyncio 任务。
- 领域层与 HTTP、MongoDB、CNINFO、模型客户端隔离，便于测试。
- CNINFO 适配器实际接入前先以小范围请求验证 query 响应字段、分页语义和市场覆盖；不会将浏览器会话 Cookie 写入实现。

## 验收标准
1. 任意已确认的日期范围可创建分析任务并显示进度。
2. 任务分页拉取公告，候选 PDF 解析并进行结构化分析。
3. 每个高置信度结论有分类、明确证据、原文位置/片段和规则说明。
4. 结果按四视图过滤，可查看事件时间线与源文件链接。
5. 重跑采用增量逻辑，失败项可定向重试。
6. 页面关闭后，本地服务继续任务；页面重开后可读取 MongoDB 中的任务与结果。
