# 公告分类细化设计

日期：2026-08-03

## 目标

修正回购公告、股权激励名单公告和土地购置进展公告的分类，使列表只保留有投资研判价值的机会或风险事件，同时继续以 PDF 原文作为最终证据。

## 范围

- 不变更页面布局、抓取流程、模型配置存储方式或数据库类型。
- 不新增 OCR，不在服务端保存模型密钥。
- 仅调整标题候选筛选、PDF 规则兜底、历史记录的重置逻辑和测试。

## 分类规则

### 标题级窄排除

- 标题包含“激励对象名单”时，不把限制性股票/股权激励类公告作为机会候选。
- 标题同时包含“购买土地使用权”和“进展”时，不把该公告作为“产能投产和重大项目”机会候选。

这些排除只针对纯名单披露和土地取得/手续进展；股权激励方案或实施、项目开工、试生产、竣工、投产等既有高召回信号继续保留。

### PDF 证据兜底

- 回购进展：标题同时包含“回购”和“进展”，且 PDF 明确给出截至日和累计回购事实时，确认为机会。摘要以“回购进展：”开头，并如实描述已回购或尚未实施的状态。
- 回购方案：标题同时包含“回购”和“方案”，且 PDF 明确披露资金下限和上限时，确认为机会。摘要为“计划回购金额：X 至 Y。”

上述规则优先于模型返回的空标签，但不跳过 PDF 下载或证据校验；模型仍会参与普通候选公告的研判。

## 历史数据修正

启动时按标题模式重置受本次规则影响的已分析记录：

- 回购进展、回购方案记录重置为 `candidate`，清空旧结果；用户下一次点击“分析”后将按新 PDF 规则重新生成结论。
- “激励对象名单”和“购买土地使用权…进展”记录改为 `dismissed`，清空旧机会标签、摘要和证据。

不按公告 ID 硬编码，确保相同类型的历史数据得到一致处理。

## 验证

新增单元测试，覆盖：标题排除、回购进展与回购方案的 PDF 兜底、历史修正；最后运行全部测试、Python 编译检查和本地健康接口检查。

## 页面结构（A：纯表格工作台）

- 公告列表采用一个标准数据表格，不使用公告卡片或大区域块。
- 页面顶部仅保留紧凑工具栏：时间范围下拉框、手动抓取按钮、分析按钮、结果视图下拉框。
- 时间范围下拉框标签为“时间”，选项固定为“今天”“最近 2 天”“最近 3 天”。选择后同步更新抓取日期范围；“今天”指 2026-08-03（运行时按本地日期计算）。
- 抓取与分析中的任务使用工具栏下方的一行紧凑任务状态条展示：任务类型、状态、已处理数/候选数、失败数和进度。页面刷新后继续通过现有活动任务接口恢复显示。
- 表格列固定为：时间、代码、简称、公告标题、分析结果；表头使用 sticky 定位，列宽固定，切换“当前队列 / 全部抓取 / 机会 / 风险”时不改变表头或列宽。
- 公告标题维持 PDF 超链接；无须额外“原文 PDF”列。

## 页面验证

- 手动切换三个时间范围，确认日期参数正确。
- 任务创建后和页面刷新后，任务状态条均可见。
- 切换结果视图后，表格列和表头宽度保持不变。
