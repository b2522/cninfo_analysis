# 分阶段公告采集与分析设计

## 目标
将“抓取即全量分析”改为两步：先抓取并按公告 ID 去重入库，再由用户触发对未分析公告进行标题高召回筛选和 PDF 原文模型分析。主表只展示候选、机会、风险和分析失败记录。

## 已确认规则
- 抓取范围支持手动日期与最近 2/3/7 天；定时任务在本地服务运行期间每天 19:00（Asia/Shanghai）抓取最近 2 个自然日。
- 巨潮请求沿用 POST `/new/hisAnnouncement/query`，`column=szse`，从第 1 页分页到 `totalpages` 的零基最大页。
- 公告以 `announcement_id` 唯一；重复抓取更新采集信息，不覆盖已有模型结论。
- “分析未分析公告”只处理尚无模型结论的记录：先标题筛选，命中后才下载 PDF、调用模型；已有结论不再调用模型。
- 页面使用亮色主题，主表为“时间｜代码｜简称｜公告标题｜分析结果”；分析结果表头下拉筛选为全部相关、机会、风险。

## 高召回过滤
标题筛选分为明确关键词和“主题词 + 事件词”组合词。定期报告、业绩预告、业绩快报一律作为候选，避免遗漏业绩增长或业绩大降。标题筛选仅决定是否调用模型；模型根据 PDF 原文决定是否保留并输出机会或风险。

## 业务分类
机会：业绩增长、并购重组和资产注入、产品获批和技术突破、产能投产和重大项目、回购和增持、终止减持和未减持。

风险：大股东减持/质押/股权变动、重大合同违约或经营风险、业绩大降。

## 数据状态
每条公告保存抓取元数据、标题候选分类、标题筛选版本与以下状态之一：`new`、`candidate`、`analyzing`、`confirmed`、`dismissed`、`failed`。主表仅返回 candidate/analyzing/confirmed/failed；dismissed 与从未筛选到的原始公告仅用于去重和后续规则升级再筛选。

## 定时任务边界
使用应用进程内调度器。服务停止时不会在 19:00 执行；服务再次启动后恢复后续每日调度。定时抓取不包含模型调用。
